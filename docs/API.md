# Library API

Import only from `joons-mcp-audit-trail`; internal modules are not public interfaces. All file operations are offline. Paths are explicit and there is no configuration discovery. Every function that touches a file returns a promise.

## Exports

- `appendRecord(logPath, event, {keyFile, now})` resolves to `{seq, hash}`. The third argument is an options object; leaving it out, `undefined` and `null` all mean no options. `event` has `type` and optionally `actor`, `tool`, `outcome`, `data` and `time`; any other key is rejected. The event and the time are validated (and the data is copied into a plain snapshot, so getters and shared references cannot change what is written) before any file is opened or created. `keyFile` is the path of a key file (required for a keyed log, refused for a plain one, and it decides the mode when the log is created); exactly one trailing line terminator (`\n` or `\r\n`) is removed from its content, and a key made only of line terminators is `key_invalid`. An explicit time is `event.time`; it must be an ISO string with a fraction of exactly three digits when present, and a time earlier than the last record rejects with `invalid_record` and nothing is written (equal times are accepted). Without `event.time` the default clock is used: `now` (an ISO string, a `Date`, or a function returning either) or else the current time. It is sampled only after the lock is held and is clamped to the last record's time when it would be earlier (a backwards clock step cannot make an append fail), so concurrent default-clock appends never fail for time order. The first append also uses it for the header. Each append takes two locks (see SECURITY.md). The stored line is the canonical JSON of the record. There are no other options. `actor` and `tool` are checked when writing: besides the character rules in [FORMAT.md](FORMAT.md) (decided by the Unicode data of the running Node.js), the literal name `(other)` and a name that starts or ends with a space are refused with `invalid_record`.
- `verifyLog(logPath, {keyFile, anchorFile, requireKeyed})` resolves to `{ok, records, headHash, mode, findings, anchor}`. `records` counts lines including the header. Each finding is `{kind, seq, detail}` (reported once per kind, line and detail) and `anchor` is `null` or `{ok, detail}`. A finding makes `ok` false; callers must check it. A keyed log without `keyFile` rejects with `key_required`. When `keyFile` is given and the header is not keyed the report holds `key_mismatch` with detail `header_not_keyed`. `requireKeyed: true` needs `keyFile` (otherwise it rejects with `usage_error`) and produces the same finding for a plain header. A log with more than 1,000,000 lines is reported as findings, not as an error.
- `createAnchor(logPath, {keyFile})` resolves to an anchor object (see [FORMAT.md](FORMAT.md)). It verifies the log first and rejects with `log_corrupt` if the log has findings, with `key_invalid` if the key does not belong to the log (wrong key, or a key for a plain log) and with `key_required` for a keyed log without a key. Store the result apart from the log; the library does not write it to disk.
- `readRecords(logPath)` returns an async iterator that streams the file. Parsable lines yield `{record, line, lineNo, canonical}`, where `line` is the raw decoded line and `canonical` says whether it equals `canonicalize(record)`; other lines yield `{error, lineNo}` with `error` one of `bad_json`, `long_line`, `bad_encoding` (invalid UTF-8 or a byte-order mark) or `partial_last_line`. It does not check hashes and does not check that a record is an object, and it applies no name rules. Failures to open or read the file, and global limits, reject.
- `summarize(logPath, {details})` resolves to `{records, from, to, type, actor, tool, outcome}`. `records` counts events without the header; `from` and `to` are the earliest and latest event time compared as instants. Each of the four name fields is `{distinct: n}` or, with `details: true`, an object of name to count. A field holds at most 10,000 distinct names, and a name longer than 128 code points is never stored; both are counted under `(other)`, which is not counted in `distinct`. The rendered details output of the command line (`summary --details`, any format) is limited to 16 MiB. It rejects with `log_corrupt` if a line is damaged, not canonical, or not shaped like a record, and for a zero-byte file.
- Command line only, not part of the library: `show` renders at most 10,000 records and at most 16 MiB in total (every byte written, the closing tail included); beyond either it fails with `limit_exceeded`. A range wider than 10,000 records is a usage error only when both `--from` and `--to` are given. `--data` numbers are read by value (`1.0` and `1e2` are stored as `1` and `100`, a non-integer is refused); a data file above 32 KiB is `limit_exceeded`, a canonical form above 32 KiB inside a smaller file is `invalid_record`.
- `canonicalize(value)` returns the canonical JSON text and throws `invalid_record` for unsupported values (floats, unsafe integers, `undefined`, functions, cycles, non-plain objects, more than 100,000 nodes). `hashRecord(record, keyBufOrNull)` returns the lowercase hexadecimal hash of a record without its `hash` key. `GENESIS_HASH` is 64 zeros and `FORMAT` is `joons-mcp-audit-trail/log`.

```js
import {appendRecord, verifyLog, readRecords} from 'joons-mcp-audit-trail';

await appendRecord('audit.jsonl', {type: 'tool.call', outcome: 'ok'}, {});
const report = await verifyLog('audit.jsonl', {});
if (!report.ok) throw new Error('verification failed');
for await (const item of readRecords('audit.jsonl')) {
  if (item.error) throw new Error('damaged line ' + item.lineNo);
  console.log(item.record.seq);
}
```

## Errors and findings

Operations reject with an error whose `kind` is one of `input_unreadable`, `invalid_record`, `log_corrupt`, `limit_exceeded`, `credential_detected`, `key_required`, `key_invalid`, `usage_error`, `output_error`, `lock_timeout` and `internal_error`. Errors carry only that kind: no path, content or key material.

Verification findings have `kind` `bad_header`, `bad_record`, `hash_mismatch`, `chain_break`, `seq_gap`, `time_regress`, `mode_change`, `key_mismatch`, `truncated_tail`, `anchor_mismatch` or `trailing_garbage`, plus `truncated_report` after the first 100. Their `detail` strings are `header_invalid`, `record_invalid`, `line_not_canonical`, `hash_differs`, `prev_differs`, `seq_not_contiguous`, `time_earlier_than_previous`, `anchor_mode_differs`, `key_id_differs` (also `header_not_keyed` for `key_mismatch`), `log_shorter_than_anchor`, `anchor_head_differs` (also `anchor_hash_invalid` and `anchor_invalid` for `anchor_mismatch`), `unterminated_or_extra_line` and `more_than_100_findings`. A wrong key is a finding, a missing key is an error, and a log shorter than its anchor is `truncated_tail`. See [FORMAT.md](FORMAT.md).
